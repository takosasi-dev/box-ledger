# ボードゲーム・カードゲームのコレクション管理(BoxLedger)

> **開発中。実機では未確認。** ビルドと単体テストは通していますが、端末に入れて動かす確認はまだしていません。

持っているボードゲーム・カードゲームと、遊んだ記録(だれと・スコア・勝ち負け)、貸し出しを書き留める Android アプリです。

- パッケージ名: `io.github.takosasidev.boxledger`
- **完全オフライン。`INTERNET` の権限を宣言していません。** 記録と写真は端末の中だけに保存し、外へ送りません。バーコードの画像も端末の中だけで処理します。ゲームの情報をネットから取ってくる機能はありません(名前は自分で打ち込みます)。
- Android 8.0(API 26)以上
- このリポジトリには、今は Android 版(`android/`)だけがあります。Windows 版はまだありません。

## 機能

要件定義書の機能要件(FR)ごとの状態です。「作った」は、ビルドが通り、判定のロジックを単体テストで確かめた物です(画面の動きは実機未確認)。

- **Windows 版との間でのバックアップの往復の確認**: Windows 版がまだ無いためです。形式は Windows 版の要件定義書 §6 の文から作り、Android 版の中での往復(書いて読む)と追加取り込みを単体テストで確かめています。暗号化した zip を Windows 版で開けるかも未確認です。

- 効果音: Windows 版の設定 `soundEnabled` は読み書きしません。
- バーコードを読んだときの「過去の登録からの名前の候補」: 未登録の番号は、番号だけを引き継いで手で入力します。
- 返却のお知らせの日と時刻の設定: 前日と当日の 9 時ごろに固定です。
- バーコードの読み取りの速さの計測と、端末でのマイグレーションのテスト(まだ版 1 だけのため)。

## 要件定義書から変えた所

- **バーコードの読み取りは ML Kit ではなく ZXing**(`com.google.zxing:core`、Apache-2.0)を使います。ML Kit は Google の独自の規約の下で配られているためです。読む形式は EAN-13(JAN)・EAN-8・UPC-E です。UPC-A は、先頭に 0 を付けた 13 桁の EAN-13 として読みます。
- パッケージ名は `io.github.takosasidev.boxledger` です(要件定義書の例の名前は使っていません)。
- アプリロックは、アプリ独自の PIN ではなく端末のロック解除の画面を使います。
- 返却の見回りは、AlarmManager の 1 日 1 回(時刻のずれを許すアラーム)と、アプリを開いたときに行います。

## バックアップの形式

zip の中身は `manifest.json`・`data.json`・`photos/` です。参照は数値の id ではなく uuid で行い、日付は `yyyy-MM-dd`、日時は UTC の ISO 8601、色は `#AARRGGBB` で書きます。読み書きと検証は `android/core/src/main/kotlin/.../core/backup/` にあります。

## 構成

| モジュール | 中身 |
|---|---|
| `android/core` | Android に依らない Kotlin。勝率・集計・絞り込み・未プレイの提案・順位の自動の提案・バックアップの形式と検証・追加取り込み・バーコードの読み取り。`gradlew :core:test` で単体テストが走ります。 |
| `android/app` | Compose の画面、Room、通知、Glance のウィジェット、SAF、CameraX。 |

## ビルド

JDK 17 と Android SDK(platform 35 / build-tools 35)が要ります。`android/local.properties` に `sdk.dir=<SDK の場所>` を書くか、環境変数 `ANDROID_HOME` を決めてから:

```sh
cd android
./gradlew :core:test        # ロジックの単体テスト
./gradlew assembleDebug     # -> app/build/outputs/apk/debug/app-debug.apk(debug の鍵で署名)
```

## 権限とその理由

自分で宣言している権限:

| 権限 | 理由 |
|---|---|
| `CAMERA` | バーコードの読み取りと、箱の写真の撮影。使うときに許可を求めます。断っても、手入力と写真の選択で使えます |
| `POST_NOTIFICATIONS` | 貸し出しの返却のお知らせ(Android 13 以上。設定の画面から許可を求めます) |
| `RECEIVE_BOOT_COMPLETED` | 端末の再起動で消える、1 日 1 回の見回りのアラームを積み直すため |

`INTERNET` は宣言していません。ライブラリが足す権限(ビルドした APK に入ります):

| 権限 | 出どころ | 実際に使うか |
|---|---|---|
| `ACCESS_NETWORK_STATE` | Glance → WorkManager | 使わない。`INTERNET` が無いので通信そのものができない |
| `WAKE_LOCK` / `FOREGROUND_SERVICE` | Glance → WorkManager | Glance がウィジェットを描き直すときに使う。自分では WorkManager に仕事を登録していない |

写真の選択と、バックアップのファイル・フォルダの選択は、端末の選択画面(Photo Picker / SAF)を使うので、ストレージの権限は要りません。

## データの扱い

- `android:allowBackup="false"` なので、Google のクラウドのバックアップには乗りません。退避の手段は、アプリの中のバックアップ(zip)だけです。
- 自動バックアップと、取り込みの前の退避の zip は、パスワードなしで書き出します。自動バックアップの保存先のフォルダは自分で選びます。取り込みの前の退避はアプリの中に置き、新しい 3 件だけを残します。
- プレイヤーには名前とメモだけを持ちます。パスワードやアカウントなどの認証の情報は保存しません。
- DB の版を上げるときは、`AppDatabase.MIGRATIONS` に Migration を足し、`android/app/schemas/` にできた JSON を commit します。`fallbackToDestructiveMigration()` は使いません。
